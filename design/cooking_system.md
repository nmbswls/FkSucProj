# 轻量非战斗烹饪系统（核心初版）

## 本阶段边界

当前版本只实现料理定义、固定配方、配方解锁查询、材料预览、批量制作和烹饪 UI。料理继续复用通用物品与送礼系统，不建立独立料理背包。

本阶段明确不实现：

- 城镇宴会结算与城镇建设进度。
- 酒馆建筑、订单周期、收益和面板。
- 古老者献礼、cult seat 或科技节点联动。
- 主角食用效果、生命恢复、属性强化或战斗 Buff。
- 炼金式素材属性、标签合成和替代材料。

这些外围出口必须在各自建筑、内容来源和 UI 流程确定后，由对应模块持有配置并消费料理，不能先在烹饪模块中建立平行状态。

## 核心数据

`CookingRecipe` 是唯一配方来源：

- `ingredient_item_ids` 与 `ingredient_counts` 一一对应，构成不可替代的固定成本。
- `result_item_id` 与 `output_count` 定义固定产出。
- `level` 表示制作档次。
- `rarity` 只表示原料获取难度。
- `primary_type` 是唯一主类型。
- `style_tags` 最多两个，只描述料理风格。
- `unlock_key` 是可选通用世界开关；来源模块负责设置开关。
- `description`、`icon_sprite` 与 `unlock_hint` 只服务内容表现。

等级、稀有度、主类型和风格标签互不换算。烹饪系统不读取 mindfacet 的内部类别，也不把料理标签作为配方公式。

## 初版类型与标签

主类型：主食、主菜、汤羹、甜点、饮品、拼盘。

通用风格：家常、丰盛、甜味、清爽、精致、节庆、异域、怀旧。每道料理允许零至两个风格；怀旧只描述料理的记忆感或旧式风味，不代表古老者专属关联，也不读取 mindfacet 属性。古老者、角色名、任务名及 mindfacet 属性不进入风格标签。

稀有度：常见、少见、稀有、珍贵、有限。有限表示原料或获取次数受控，不是独特料理品类。

## 制作事务

每道固定配方同时配置普通产物与优质产物两个物品 ID。每个产出单位独立按固定 10% 概率产出优质物品，批量制作可以同时得到两种产物；该概率不是配方属性，也不参与材料组合计算。物品表的 `cooking_ingredient` 布尔字段决定物品是否允许进入料理固定配方，料理验证器会拒绝未标记的原材料。

`CookingCraftService.BuildQuote` 负责一次无副作用预检：

1. 校验批次数量、配方结构和解锁开关。
2. 汇总主背包、mindfacet 背包、重要物品、特殊背包和仓库的持有量。
3. 计算批量材料需求和产出数量。
4. 检查材料与产出空间。

`TryCraft` 只接受通过预检的请求。扣除过程中若库存发生意外变化，会回退已经扣除的材料；产出发放异常时会移除本次部分产出并恢复材料。普通玩法仍应避免在同一帧并发修改玩家库存。

料理物品不配置 `item_use`。配置验证器会将任何带 `item_use` 的料理视为错误。

## mindfacet 消耗

初版同时提供低档与高档消耗：

- `酣眠果羹`：低档、可重复制作，消耗一份 mindfacet。
- `灯影薯汤`：中档，消耗一份 mindfacet。
- `夜色盛宴拼盘`：高档，消耗两份 mindfacet，并需要普通农产与怪物素材。
- `往日蜜露`：有限档配方，消耗两份 mindfacet；当前只定义制作与解锁提示，不实现献礼出口。

新增稳定 mindfacet 来源时，应检查对应获取档位是否存在至少一个可重复料理消耗配方。

## 烹饪 UI

`CookingPanel` 使用项目 `PanelBase` / `PanelWithInput` 模式，Prefab 位于 `Assets/Resources/UI/Prefabs/CookingPanel.prefab`。

- 左栏为“全部 / 可制作”分段筛选和固定配方列表。
- 右栏展示料理描述、等级、稀有度、主类型、风格和材料持有量。
- 材料行会显示背包持有量；拥有的可烹饪原材料可点击选中，左侧配方列表会筛选包含所选原料的固定配方。该选择只用于筛选，不改变固定配方成本。
- 批次使用减号、数值、加号控件，范围为 1-99。
- 制作按钮只在配方已解锁、材料充足且普通/优质产物空间都足够时启用；确认后按每个产出单位 10% 概率生成优质物品。
- 锁定配方仍可查看，并显示配置提供的解锁提示。
- 配方条目和材料条目均保存在面板 Prefab 内作为模板。
- 使用由 `MSYH.TTC` 生成的 `MSYH Cooking SDF` 动态字体资产，覆盖初版中文内容。

面板通过 `CookingPanel.Open()` 打开。当前不绑定任何未确定的厨房或酒馆建筑；实际场景入口应在设施设计确认后接入。

## 扩展检查

新增料理只需要增加料理物品、送礼档案和固定配方。提交内容前检查：

1. 所有材料与产出物品存在。
2. 材料无重复项且数量为正数。
3. 料理没有 `item_use`。
4. 主类型唯一，风格不超过两个。
5. 等级、稀有度和标签语义没有混用。
6. `unlock_key` 的来源属于任务、关系、设施或其他真实内容模块。
7. 图标资源存在；缺图不会改变制作逻辑，但不得长期以无关物品图标代替。
