# 教团锚点系统设计

## 功能定位

锚点是教团在可探索地图中的长期据点。每张地图（`logic_area`）可以配置多个锚点，玩家通过教团相关行为积累指定锚点的进度；达到条件后，锚点永久建立。

锚点是抽象的教团系统对象，不要求对应场景中的真实物体。它由地图配置和教团运行时状态共同表示，只有教团相关页面需要展示每个 `logic_area` 的锚点信息。

如果需要地图表现，可以额外配置一个 prefab，并通过 `ShowCondition` 在对应锚点建立后显示。这个 prefab 只是纯展示，不是锚点状态的载体，也不参与锚点逻辑。场景中的特殊交互物则只是玩家执行教团行为的一种入口。

当前不实现锚点拆除、衰减或升级。锚点一旦建立，除非未来明确加入撤销规则，否则永久有效。

## 核心概念

### 锚点

锚点属于 `logic_area`，通过 `anchor_id` 区分。同一地图可以有多个锚点，每个锚点拥有独立的显示条件、建立条件、进度和建立后的产出规则。锚点信息主要由教团页面展示；地图 prefab 是否存在只决定是否有额外的场景表现。

锚点建立后：

- 按配置周期产出信仰；
- 可以产出普通物品；
- 为入梦玩法预留资源产出，但当前不实际接入；
- 每日为所属 `region` 增加一定数量的教徒；
- 产出效率受所属 `region` 的教徒数量影响。

### 教徒

教徒是区域级资源，按大区域 `region` 存储。教徒不是 `logic_area` 的值，也不在每个锚点上复制保存；锚点结算时读取其所属 `region` 的教徒数量。

运行时沿用现有的区域教徒数据（当前对应 `LinkerCountByRegionKey`）。

### 眷恋者

眷恋者就是全局的 `FallenAmount`，对应当前运行时的 `PlayerSystemManager.TotalFallPeopleAmount` 和存档中的 `PlayerData.TotalFallPeopleAmount`。

```text
眷恋者 = 全局 FallenAmount = TotalFallPeopleAmount
```

它不等于区域教徒，也不参与教徒的区域分配。锚点可以预留眷恋者对进度的加速入口，但当前加速值固定为 0。

> 代码检索提示：如果后续需要查找“眷恋者”相关逻辑，应同时搜索 `FallenAmount`、`TotalFallPeopleAmount` 和“眷恋者”。

### 教会行为

教会行为用行为 ID 表达玩家执行的具体教团行为。特殊交互物的产出配置可以携带目标锚点 ID、教会行为 ID 和本次进度值，玩家完成交互后由教团系统将进度累计到指定锚点。

当前先不实现锚点升级，但保留以下扩展方向：锚点的每个等级关联一组教会行为 ID；只有匹配当前等级的行为才能贡献进度，或产生对应等级的效果。

## 玩家行为链路

现有“购买教团相关情报后，在地图生成特殊交互物”的机制作为第一类锚点进度入口：

```text
购买情报
  -> 进入目标 logic_area
  -> 生成特殊 InteractPoint
  -> 玩家交互
  -> 提交目标 anchor_id、教会行为 ID 和进度
  -> 教团系统累计锚点进度
```

情报系统负责情报购买、有效期和交互物生成；教团系统负责验证目标锚点、检查显示/行为条件、计算进度并更新锚点状态。交互物不直接修改锚点存档。

## 配置职责

只需增加锚点相关配置，用于说明：

- 哪些锚点属于哪个 `logic_area`，以及各自的 `region` 归属；
- 锚点何时可显示、建立需要什么条件和多少进度；
- 建立后的周期产出内容、周期和效率规则；
- 每日增加的区域教徒数量；
- 预留的入梦资源产出；
- 未来锚点等级对应的教会行为 ID 集合。

特殊情报或特殊交互物的配置只需声明其目标锚点、教会行为 ID 和本次贡献值，不应复制锚点规则。

## 运行时职责

### `DemonCultSystem`

内聚负责锚点状态和规则：

- 查询地图上的锚点及其显示状态；
- 累计教会行为带来的锚点进度；
- 判断并永久建立锚点；
- 在日结算或周期结算时处理锚点产出；
- 根据所属 `region` 的教徒数量计算产出效率；
- 将锚点的每日教徒增加写回 `region` 级教徒资源；
- 为未来秘会任务提供“该区域存在可用锚点”的查询。

### `RumorIntelSystem` / `RumorIntelMapSpawn`

负责情报链路和特殊交互物生命周期，并向交互物注入目标锚点及教会行为信息。不负责锚点进度、锚点产出或教徒结算。

### 日期结算系统

日期系统只负责编排教团日结算时机，具体锚点产出和教徒增加规则留在 `DemonCultSystem`。

## 秘会与传教

秘会是数量较少、具有状态、可由玩家派遣执行任务的教团行动单位。秘会系统当前尚未完善，因此锚点只需要预留“可派遣任务”的查询边界，不实现派遣、行动周期、单位状态或奖励结算。

“传教”是未来秘会任务系统中的一种具体任务类型。它可以在任务周期结束后增加目标 `region` 的教徒，但当前不接入锚点系统，也不提前实现任务流程。

## 实现边界

后续实现按以下顺序推进：

1. 增加锚点配置和锚点运行时存档；
2. 在 `DemonCultSystem` 接入锚点查询、进度累计、永久建立和周期结算；
3. 扩展特殊交互物，使其提交目标锚点和教会行为；
4. 将锚点产出及教徒增加接入日期结算；
5. 秘会任务系统完成后，再接入“传教”任务。

本阶段不做锚点升级、不做固定村民逻辑、不把教徒复制到 `logic_area`，也不把眷恋者改造成区域资源。
