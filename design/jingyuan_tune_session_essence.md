# 调精：优质精华与临时单局养成设计

## 1. 设计结论

调精从“长线固定养成”调整为“临时性的单局构筑”。

- 长线只保留**精型图鉴、来源记录、解锁记录和配方可见性**，不再直接提供永久属性。
- 玩法主体是不可堆叠的**优质精华实例**。
- 优质精华只有装备到玩家身上后才提供属性和被动。
- 精华浓度决定主词条强度；额外词条是随机奖励，不作为稳定成长的唯一来源。
- 每件精华都有保质期，剩余时间归零后自然消失。
- 一次外出使用的精华构筑在出发时锁定，回到秘密基地后结算并允许重新整理。

这里的“单局”指一次外出周期，不是删档或重置角色。玩家的长期成长体现在更容易获得更好的精型、更多槽位、更高调和上限和更完整的图鉴，而不是某件精华永久留在身上。

## 2. 优质精华

### 2.1 获得来源

优质精华主要来自：

1. 事件和任务的固定或条件奖励；
2. 榨取精元时的概率掉落；
3. 后续可加入高难度内容、特殊地点和古老者相关奖励。

普通精元仍然是普通资源，不因为调精改版而失去原有的精浴、消耗和任务用途。榨取时应先完成普通精元产出，再独立进行优质精华掉落判定，避免把优质精华误做成普通精元的替代品。

### 2.2 实例字段

每件优质精华至少包含以下运行时字段：

| 字段 | 说明 |
|------|------|
| `instance_id` | 实例唯一 ID，不可堆叠 |
| `essence_type_id` | 精型 ID，引用精型定义 |
| `concentration` | 当前浓度，建议使用离散档或整数范围 |
| `extra_affix_ids` | 额外词条列表，可为空 |
| `remaining_shelf_life` | 剩余保质期 |
| `source_type` | 事件、任务、榨取或调和产出来源 |
| `created_at` | 创建时刻，用于调试、回放和过期结算 |
| `state` | 仓库、装备槽、临时存储或已过期 |

`essence_type_id` 决定精华的主题和可出现的词条池；`concentration` 决定同一主词条的强度；`extra_affix_ids` 只提供额外奖励，不改变精型归属。

### 2.3 精华效果

- 未装备的优质精华不提供属性。
- 装备中的精华按照精型和浓度计算主词条。
- 额外词条在装备后同时生效。
- 同一精型是否允许重复装备，首期建议**允许**，但应设置收益递减或重复限制，避免玩家只寻找一种精型。
- 精华效果只进入临时调精贡献，不写入永久 `Progression` 等级。

建议的计算结构：

```text
主词条 = 精型定义 + 浓度档位
额外词条 = 实例随机词条
最终效果 = 装备中的所有优质精华效果合计
```

## 3. 三类容器

优质精华不再与普通背包混用。系统拥有三类职责明确的存储空间。

| 容器 | 所在位置 | 建议容量 | 是否提供属性 | 用途 |
|------|----------|----------|--------------|------|
| **优质精华仓库** | `secretbase` 专用设施 | 初始约 50 格 | 否 | 长期保存尚未使用或暂时不用的精华 |
| **装备槽** | 玩家身上 | 1～5 格 | 是 | 当前外出周期的生效精华 |
| **临时存储槽** | 玩家身上 | 10～20 格 | 否 | 外出中获得、待整理的精华 |

容量都由进度配置决定：装备槽和临时存储槽随功能、剧情或成长阶段增加；仓库容量也可以在秘密基地扩建后增加，但首期目标约为 50 格。

### 3.1 装备槽

- 出发前可以自由装入、取出和替换。
- 进入单局后锁定，外出期间不可更换。
- 只有装备槽中的精华计算主词条、额外词条和收获修正。
- 离开秘密基地时至少开放 1 格，后续逐步成长至 5 格。

### 3.2 临时存储槽

- 外出期间获得的优质精华优先进入临时存储槽。
- 临时存储槽中的精华不提供属性。
- 回到秘密基地后可以转移到仓库、装备槽或调和输入区。
- 容量不足时应使用明确的获得失败提示和选择界面，不应静默删除。
- 首期建议从 10 格成长到 20 格。

### 3.3 仓库

- 仓库是秘密基地中的长期管理设施，不参与外出即时战斗。
- 仓库 UI 显示精型、浓度、额外词条、剩余保质期和来源。
- 仓库满时，任务奖励和榨取掉落必须提供“放入临时存储 / 放弃 / 返回”的明确选择。
- 优质精华过期时，无论在仓库、装备槽还是临时存储槽，都统一清理并提示玩家。

## 4. 调和玩法

调和是据点内用于提升优质精华浓度的操作，具体操作形式和资源消耗暂未最终确定，但数据结构按“输入一个或多个精华，输出一个新实例”设计。

首期建议只实现一种核心操作：

| 操作 | 输入 | 输出 | 备注 |
|------|------|------|------|
| **调和 / 浓缩** | 一件优质精华 + 精元或触媒 | 同精型新精华，浓度提高 | 新实例继承或重新掷额外词条，旧实例消耗 |

后续可加入：

- 同精型合成：稳定提升浓度，但消耗多个实例；
- 触媒调和：提高浓度或锁定某个额外词条；
- 稳定调和：延长保质期，但不提高或少量降低浓度；
- 混合调和：消耗两种精型，产生特殊联动精华。

调和不应直接修改装备中的实例。装备中的精华必须先卸下，调和完成后生成新实例，再由玩家决定是否重新装备。

## 5. 浓度与词条

### 5.1 浓度

浓度是优质精华的核心数值，首期建议使用 5 档离散等级，避免无限浮点成长：

| 浓度档 | 语义 | 效果方向 |
|--------|------|----------|
| 1 | 稀薄 | 只有基础主词条 |
| 2 | 稳定 | 基础强度提高 |
| 3 | 浓郁 | 达到常规有效强度 |
| 4 | 高浓度 | 明显强化主词条 |
| 5 | 极浓 | 高收益，同时可增加调和成本或过期压力 |

浓度档的实际数值和效果曲线交由配置决定。浓度不再写入玩家全局属性 `TiaoJingConcentration` 作为唯一来源，而是落在每件优质精华实例上。

### 5.2 额外词条

额外词条是优质精华的奖励机制：

- 词条数量、稀有度和词条池由精型与掉落来源决定；
- 高浓度可以提高额外词条出现概率或词条品质，但不保证必得；
- 任务和特殊事件可以直接奖励带指定词条的精华；
- 词条必须有清晰的来源和可读的数值，不使用隐藏的永久成长。

## 6. 保质期

保质期是精华的核心取舍，不是装饰字段。

- 剩余时间随游戏时间自然减少；
- 装备、仓库和临时存储中的精华都正常计时；
- 进入菜单、暂停或读档时是否冻结，必须与项目的 LogicTime 规则统一；
- 过期后实例销毁，不转化为普通精元，除非未来专门配置回收规则；
- UI 必须显示剩余天数或时间段，并在临近过期时提示；
- 调和生成的新实例应拥有新的保质期，是否继承旧实例剩余时间需要明确配置。

首期建议以**游戏日**作为保质期单位，而不是现实时间，避免玩家离线造成不可预期损失。精华可配置 1～7 个游戏日的保质期范围。

## 7. 单局边界与锁定

推荐单局边界为：

```text
秘密基地整理 / 调和 / 装备
    -> 确认出发，锁定装备槽
    -> 外出期间只使用装备效果，获得的精华进入临时存储槽
    -> 返回秘密基地，结算本局，解除锁定
```

首期建议：

- 从 `secretbase` 离开后锁定装备槽；
- 外出期间不能调和、不能把临时存储精华装入装备槽；
- 战斗失败、主动返回和正常完成都走同一个“返回结算”流程；
- 若玩家在外出期间强制退出，按项目现有存档策略恢复到最近一次合法的单局快照；
- 失败是否保留临时存储中的精华，需要作为单独的风险规则配置，不隐含在系统代码里。

## 8. 长线系统的改造边界

现有调精代码仍包含长线固定养成，需要按下表迁移：

| 现有系统 | 新定位 |
|----------|--------|
| `JingYuanCodexProgress` | 保留为图鉴、精型和来源解锁记录；不直接提供属性 |
| `EquippedJingYuanTunes` | 从 `PlayerJingYuanCodexSystem` 和玩家存档中移除；未来由独立优质精华存储系统管理实例 ID |
| `TiaoJingConcentration` | 从玩家实体资源和旧调精系统移除；浓度只存在于优质精华实例 |
| `JingYuanTuneTier` | 逐步废弃；主词条改由优质精华效果表按“精型 + 掉落等级 + 浓度档”读取 |
| `JingYuanCodexLevel` | 改为图鉴/解锁信息，不能直接注入永久属性 |
| `jingyuan` 道具 | 保留为普通精元资源 |
| 榨取精元流程 | 增加独立的优质精华掉落判定 |
| `JingYuanTunePanel` | 拆为秘密基地仓库 / 调和页，以及出发前装备页 |

迁移时必须避免旧存档把原有永久调精属性继续带入新系统。旧的长期等级可以转为图鉴解锁、初始精华奖励或调和配方解锁，但不能直接继续作为永久属性源。

## 9. UI 结构

### 9.1 秘密基地：优质精华仓库

- 仓库格子显示精型图标、浓度档、额外词条数量和保质期；
- 支持筛选精型、浓度、词条和剩余时间；
- 支持查看详情、装备、放入调和、销毁；
- 满仓时明确显示容量和处理选项。

### 9.2 秘密基地：调和台

- 只显示可作为输入的优质精华和调和材料；
- 明确展示输入、浓度变化、保质期变化、词条继承/重掷结果；
- 调和确认前展示“旧实例将被消耗”的提示。

### 9.3 出发前：装备页

- 显示当前装备槽容量和临时存储槽容量；
- 可从仓库选择精华装入装备槽；
- 显示本次外出的主词条、额外词条和预期收获修正；
- 确认出发后显式显示“装备已锁定”。

## 10. 首期范围

首期只做以下闭环：

1. 事件/任务或榨取流程概率产出优质精华；
2. 优质精华有精型、浓度、额外词条、保质期；
3. 秘密基地仓库可保存约 50 件；
4. 玩家拥有 1～5 个装备槽和 10～20 个临时存储槽；
5. 装备后主词条和额外词条生效；
6. 外出锁定装备，临时获得的精华进入临时存储；
7. 回到秘密基地后解除锁定并清理过期精华；
8. 实现一种提升浓度的调和操作。

首期不做：混合精型联动、复杂词条重铸、实时离线保质期、精华掉落到地面、完整的永久调精属性树。

## 11. 待确认问题

以下问题会直接影响数值和存档结构，需要在进入代码实现前确定：

1. **单局结束条件**：主动返回秘密基地就结束，还是必须完成地图目标/结算点才结束？
2. **失败处理**：战败后装备中的精华、临时存储中的精华分别如何处理？保留、损失一部分，还是全部保留？
3. **保质期单位**：是否确定使用游戏日？暂停和离线是否冻结 LogicTime？
4. **浓度提升**：调和是稳定提高一档，还是有成功率和失败代价？
5. **额外词条**：词条是否允许调和重掷？是否允许锁定词条后继续调和？
6. **重复精型**：装备槽是否允许装备同一精型多次？如果允许，是否递减？
7. **仓库扩容**：50 格是初始容量，还是首期固定容量？
8. **榨取掉落**：优质精华掉落概率按 NPC、精型、榨取方式还是事件配置？

## 12. 代码接入预览

预计新增或调整的边界：

- `PremiumEssenceInstance`：优质精华实例；
- `PremiumEssenceStorage`：仓库、装备槽、临时存储的容量和转移规则；
- `JingYuanRunLoadout`：出发快照与锁定状态；
- `JingYuanEssenceSystem`：掉落、装备、调和、过期和结算；
- `JingYuanCodexSystem`：降级为图鉴/精型解锁，不再作为永久属性源；
- `JingYuanEssenceType`、`JingYuanEssenceAffix`、`JingYuanEssenceConcentration`：独立配置表；
- `EJingYuanType`：跨系统精型枚举，作为精型信息、优质精华、掉落池和 Character 固定绑定的主键；
- `JingYuanTypeInfo`：名称、图标、对应种族、匹配标签和排序；
- `JingYuanPremiumEssence`：优质精华定义、基础保质期和额外词条池；
- `JingYuanPremiumEffect`：精型、掉落等级、浓度下限到属性加成的映射；
- `JingYuanEssenceLevelMap`：NPC 等级区间到优质精华等级的掉落映射；
- `JingYuanTypePoolEnum` / `NamedNpcJingYuanType`：随机精型池和 Character 固定精型配置；
- `JingYuanTunePanel`：拆为仓库/调和/出发装备三个工作流页面。

系统应通过通用属性贡献接口提供当前装备精华的临时效果，避免把优质精华字段添加到通用玩家属性或普通 ItemStack 语义中。
